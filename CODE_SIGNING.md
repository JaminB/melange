# Code signing

Melange releases from 0.3.1 on are code-signed. You can check the signature in the file's *Properties > Digital Signatures* tab, or with `Get-AuthenticodeSignature <file>` in PowerShell.

- **What is signed:** `melange.asi`, `Melange.exe` and `tools\xomtool.exe` in the release zip. `dinput8.dll` is the unmodified [Ultimate ASI Loader](https://github.com/ThirteenAG/Ultimate-ASI-Loader) and is not signed by Melange.
- **How:** the [`release` workflow](.github/workflows/release.yml) builds the binaries from this repository's public source on a GitHub-hosted runner when a version tag is pushed, signs them with Azure Artifact Signing (SHA-256, timestamped), checks the signatures, and attaches the zip, its SHA-256, and its update manifest `melange-<version>.json` (the zip's name, size and SHA-256) to the GitHub release. No locally built binary is ever signed.
- **By whom:** the certificate is issued to the maintainer, JaminB, who is the only committer, reviewer and approver of releases.
- **Where:** https://github.com/JaminB/melange/releases is the only source of signed Melange releases. Forks and mirrors cannot produce them.
- **Updates:** `Melange.exe` installs a new release only when the zip matches the size and SHA-256 in the release's manifest, and the new `Melange.exe` and `melange.asi` carry a valid signature from the same publisher as the running `Melange.exe`. "Same publisher" means the certificate's subject and its issuing organisation match; the short-lived certificates themselves change every few days. A developer build is unsigned, so it skips that comparison and says so in its log.
- **Privacy:** signing transfers no user data. Melange collects no telemetry. It contacts GitHub when you open the Store, when `Melange.exe` starts (to look for and download a newer Melange), and from the game at most once a day (`[Update] CheckInGame=1`). *Settings › Updates › Check for updates automatically* in `Melange.exe` turns off both automatic checks. Each request is a plain HTTPS `GET` that sends nothing about you or your game.

## The media helper (`holo-media.exe`)

Melange 0.12 can download a media pack (video playback for plugins such as Holo) into `Documents\Melange\media`. Its one executable that Melange builds, `holo-media.exe`, is signed like the rest:

- **What is signed:** `holo-media.exe` in the pack. `libmpv-2.dll` (an unmodified LGPL build by zhongfly) and `deno.exe` (the Deno project) are repackaged as published, pinned by SHA-256 in [`media/media.lock.json`](media/media.lock.json), and are not signed by Melange. Their sources and licences are listed in the pack's `SOURCES.md`.
- **How:** the [`media-pack` workflow](.github/workflows/media-pack.yml) builds the helper from `helper/holo-media` on a GitHub-hosted runner in the same approval-gated `release` environment, signs it with Azure Artifact Signing (SHA-256, timestamped), checks the signature, runs the tests and `holo-media.exe --selftest` on the packed files, and attaches `melange-media-<version>.zip` to the release `media-v<version>`. A published pack is never replaced.
- **What `melange.asi` checks:** each pack is pinned in the `melange.asi` that shipped it: the zip's size and SHA-256 and every file's size and SHA-256. Before every launch the helper and `libmpv-2.dll` are hashed again, and `holo-media.exe` must carry a valid signature from the same publisher as `melange.asi`. A developer build is unsigned, so it skips only the publisher comparison and says so in its log.
- **yt-dlp:** yt-dlp is not in the pack. The same workflow checks the newest yt-dlp release against its maintainers' GPG signature (the public key is committed as [`media/yt-dlp-public.key`](media/yt-dlp-public.key) and pinned by fingerprint) and publishes an **unsigned** manifest `media-ytdlp.json` (version, url, size, SHA-256, serial) on the rolling release `media-ytdlp`. Melange installs a yt-dlp only if its SHA-256 matches the manifest, which it fetches over HTTPS from this repository's releases, and refuses a lower serial, so it cannot be rolled back. The lane runs without an approval step, so it is deliberately not part of the signing trust: the helper, not yt-dlp, is what Melange vouches for.
